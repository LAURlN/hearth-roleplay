# Implementation contract

Working title: Hearth. Local-only, buildless, dependency-free Node 22+ app. Root owns server.mjs, src/provider.mjs, src/store.mjs, src/illustrator.mjs, src/settings.mjs, API tests, docs, scripts. Engine delegate owns src/engine.mjs and test/engine.test.mjs only. UI delegate owns public/index.html, public/app.js, public/style.css only. No dependencies, commits, publishing, paid/live inference, or further subagents by delegates.

## Engine contract

Semantic helpers: actual runs set perceptionMode:'helper'. src/semantics.mjs queues each local event with its historical character/location/event boundary, resolves per-observer deliveries and current views through the Helper model, and persists event.perceptions, event.recipients and perception_decision records. The sender remembers their own event independently. Views select established visible fact keys, update visibleCharacters and appearance memories; helper-mode contexts never infer sight from co-location. Nonempty intendedRecipients cannot be widened. Remote delivery remains explicitly addressed. No matching-location fallback is used for actual local delivery. Trial plan validation performs no helper requests or semantic state grants.

Actual time advancement awaits perception, visual updates and message checkpoint creation after each instantaneous pending event, before the next fictional boundary. Synchronous clock simulation is for validation only. Earlier message snapshots remain real prefixes of the continuation and retain only later pending work, without later knowledge. Visual replay applies only patches absent from the source snapshot; approved historical views use historical sight without changing live impairments. Explicit player-addressed remote observations are displayed without local perception rewriting. Both perceived text and source labels undergo the private-fragment guard using the author's knowledge at the source boundary.

Public awareness uses helper-authored decisions at source/movement/activity and hourly skip opportunities, with persisted publication/character/hour/activity keys (including negatives). No random probabilities select awareness. Historical snapshots exclude later same-minute knowledge and movement. Helper records carry observedAt/learnedAt while knowledge retains historical time; append order and checkpoint prefix indices stay stable. Explicit online access/restricted-publication guards remain. The reactive scheduling helper sees fresh resolved state, narrator suggestions and already-called IDs, chooses one next NPC or yields to the player, and may react to new stimuli by selecting a different/repeated actor within maxResponders. All helper failures/cancellation roll back the entire turn; debug logging remains outside rollback. Rewind/switch preserves the corresponding perceptions, visibility, awareness and knowledge.

Settings: chatEffort, characterEffort, helperEffort and illustratorEffort each default to empty/provider-default independently. Complete transports receive reasoningEffort only when selected; provider maps it to Chat Completions reasoning_effort or native Responses reasoning.effort. Image generation has no text effort. GET /api/models preserves capability metadata. UI loads real selects on Settings open/refresh, retains current/unavailable IDs and blank helper selections, and rejects stale catalog responses after proxy changes. Unsupported explicit selections surface provider errors without fallback.

Player placement: input interpretation receives recent narrator history. A separate helper resolves omitted destinations for completed observable action segments, including object interactions that establish presence. It can repair a stale current location only from retained player-action excerpts with valid checkpoint boundaries and no later established player movement. A private or speech segment cannot authorize placement. Completed new action segments carry placementResolved; playerPlacementCheckedAt prevents repeatedly reviewing the same legacy checkpoint. Internal placement_correction events synchronize records without arrival/departure observations or retroactive dialogue grants. Local NPC text resolves at that NPC's actual location even off-scene; explicit recipient restrictions are validated; local audibility and sight are helper decisions and only player-delivered observations become character messages.

Export createInitialState(setup), runTurn(options), applyAuthoredMessage(options), characterContext(state, characterId), parseJson(text), and optionally helpers. Pure world/state transformations; no filesystem/network imports. Use node:crypto for IDs. Complete inputs/outputs are serializable plain objects.

setup = {title, premise, persona:{name,description}, characters:[{name,description,appearance,personality,goals,location,online?}]}. Defaults permitted. Character IDs assigned deterministically within the saved setup using random UUID once at initialization. Player is a distinct character with id 'player'; never generate their dialogue or choices.

World state must expose {time:number, timeLabel:string, location:string, locations:string[], characters:Character[], events:Event[], publications:Publication[], exposureDecisions:Record<string,boolean>, pending:[]}. time is monotonic fictional minutes from start; timeLabel may be narrative. Character = {id,name,description,appearance,personality,goals,location,knowledge:[{id,text,source,time,eventId?}],privateState:string,online:{access:boolean,interests:string[],connections:string[]}}. Player included in characters array. Keep global truth distinct from each character's beliefs. Additional fields allowed, but preserve schema.

Message = {id,role:'player'|'narrator'|'character',characterId?:string,speaker:string,text:string,createdAt:ISODate,snapshot:WorldState}. snapshot is state immediately AFTER that message, never any subsequent events. User messages can include private thoughts/OOC; raw user text never goes into characterContext. Narrator messages can contain editorial content; use structured observations rather than globally sharing narration. All runtime objects must be cloned: editing one snapshot cannot mutate another.

runTurn({state,messages,input,settings,complete,signal,onStage}) returns Promise<{state,messages:Message[]}>. Returned messages are NEW messages only. input:string adds player message; input:null means opening/continue without inventing a player message. messages is prior branch history. createInitialState(setup) returns WorldState. settings includes roleplayPrompt, chatModel, maxResponders (default3), contextMessages(default24). complete({model,messages:[{role:'system'|'user'|'assistant',content:string}],signal,json?:boolean,reasoningEffort?:string}) returns Promise<string>. onStage(string) is optional progress. Throw on failed or malformed generation; root commits the complete turn atomically or nothing. Respect AbortSignal between calls.

applyAuthoredMessage({state,messages,message,settings,complete,signal,onStage}) returns Promise<{state,messages:Message[]}>. state is BEFORE the edited message; message is user-authored replacement with original role/speaker/characterId and new text. Preserve authored text, classify/reconcile its observable events using narrator interpretation, and attach a correct snapshot. Do NOT regenerate this edited message. Server then calls runTurn with input:null to generate revised AI continuation. Delete simply removes target and restores preceding state before continue.

Narrator understands freeform premise and mixed input; request strict JSON plans without relying on response_format. It proposes validated sequential events and advisory speaker suggestions. An independent helper chooses the next actor after perception resolves. Implement code-enforced recipients, movement/location/presence invariants, time rules (short transitions automatically; significant skips only explicit player intent), public exposure with persisted decisions, no actor access to global events/other private state, bounded response count, and fresh context after each response. Characters decide voluntary actions in their own request; a movement helper resolves physical feasibility without changing their intention. Public posts may be visible without everyone seeing them; regional disasters can confer scoped awareness. Store source/time. Wholly private input must not fall back to raw text. New character secrets/background need reconciliation. Character responses must include separated observable text/private state/movement intents; display only the player-specific perceived text; partial hearing must not expose unseen actions.

Keep validation meaningful but usable with normal model outputs: allow fenced JSON; reject invalid identities/recipients; narrator/actor retries at most once for schema correction. Never retry a safety refusal or transport error by changing model/provider. No magic keyword/rule simulation as the primary real AI backend. Include strong editable default prompts in src/settings.mjs (root).

## Storage / public story

Character prompt extension: optional Character.systemPrompt:string (default empty, max60000), accepted in setup characters and validated in imports. Settings.characterPrompt is the shared acting prompt (max60000, blank allowed). Actor generation composes general roleplay, shared actor and own individual instructions before the required protocol. Other actor contexts exclude personal prompts; narratorProjection strips systemPrompt from character records. Generated introductions always start with an empty personal prompt. POST /api/stories/:id/character-prompt {characterId,systemPrompt,expectedVersion} rejects player/unknown IDs, forks a new branch with a non-observable checkpoint, performs no model completion, and preserves original snapshots. Pre-opening prompt edits permit later establishment. Individual prompts follow rewind; global Settings prompts apply to future generations across branches.

Visual continuity: Character.visual={initialized:true,revision,facts:[{key,layer:'physical'|'presentation',text,visible,source,visibilitySource,time}],canSee?:boolean,sightSource?,initialAppearance?}. visible is the currently perceptible wording; blank means concealed. The legacy appearance string projects visible facts. Character.seenAppearance[subjectId]={name,facts:[{key,text,time}],current:[{key,text}],time,location,revision} retains an observer's last-seen details without sharing actual/hidden facts or source excerpts. Helper patches cite exact source excerpts but may synthesize concise visual descriptions. Sequential resolved boundaries and the perception helper govern current sight and selected visible fact keys; private input and pure player speech are excluded as physical-update sources. Snapshots retain original state; legacy saves initialize lazily.

POST /api/stories/:id/appearance {characterId,facts:[{key,layer,text,visible}],canSee?:boolean,expectedVersion} applies a validated human correction in a new branch and adds a non-observable narrator checkpoint, preserving the original branch. POST /api/stories/:id/metadata {title?,archived?,expectedVersion} updates global library metadata without inference or branch changes. List summaries expose archived and version; publicStory exposes archived. UI offers per-entry management, Library/Archived filters and visual correction forms. Export/import preserve visual state and validate new shapes.

Internal Story = {id,title,setup,createdAt,updatedAt,version,activeBranchId,branches:{[branchId]:{id,name,parentId,forkMessageId,createdAt,initialState,messages:Message[],illustrations:ImageRecord[]}},illustrationJob?:{id,branchId,anchorMessageId,status,error?}}.

Public story response = {id,title,setup,createdAt,updatedAt,version,activeBranchId,branches:[{id,name,parentId,forkMessageId,messageCount,createdAt}],branch:{id,name,messages:[Message without snapshot],illustrations:ImageRecord[]},world:WorldState, busy:boolean,stage:string,illustrationJob?:...}. Engine world shape is opaque to store. world is last message snapshot or branch initialState. ImageRecord={id,url,prompt,caption,createdAt,anchorMessageId,branchId,referenceIds?:[],appearanceNotes?:string}. Inspector may show full world to the human, but provider actor contexts MUST be filtered.

## HTTP API

All JSON responses, errors {error:string,code?:string}. POST/PUT bodies JSON, 2MiB limit. All writes same-origin only. GET /api/bootstrap -> {settings,stories:[{id,title,updatedAt,messageCount,branchCount}],version:'1.0.0'}; GET /api/settings -> settings; PUT /api/settings accepts settings fields and returns settings. Settings fields: proxyBaseUrl(default http://127.0.0.1:10531/v1),chatModel(gpt-6.1-sol),imageModel(gpt-image-2),roleplayPrompt,illustratorPrompt,autoIllustrate(true),imageCooldown(3),imageQuality('medium'),imageSize('1024x1024'),maxResponders(3),contextMessages(24),requestTimeoutMs(180000). Keep proxy loopback only; no API keys or paid fallback.

GET /api/models -> {connected,models:[{id,name}],error?}. GET /api/stories -> summaries. POST /api/stories body setup -> publicStory, generates opening (may take a minute). GET /api/stories/:id -> publicStory. DELETE /api/stories/:id -> {ok:true}. GET /api/stories/:id/export -> full JSON downloadable (includes branch snapshots and image data? root may export image data separately). POST /api/import body full exported story -> publicStory (validate, new story ID).

POST /api/stories/:id/turn {text,expectedVersion} -> publicStory. POST /api/stories/:id/continue {expectedVersion} -> publicStory. POST /api/stories/:id/cancel -> {cancelled:boolean}. GET story during generation returns busy/stage, used for status polling. Client AbortController + cancel endpoint to stop. Root saves complete turn atomically; no incomplete messages influence state.

POST /api/stories/:id/branch {messageId,mode:'rewind'|'edit'|'delete',text?,expectedVersion,regenerate?:boolean} -> publicStory. rewind retains selected message and state; edit/delete fork before target, edit applies replacement, then regenerate next AI continuation by default (old future stays old branch). Missing messageId + rewind means branch from initial state. POST /api/stories/:id/switch {branchId,expectedVersion} -> publicStory. POST /api/stories/:id/illustrate {messageId?,expectedVersion} -> publicStory immediately with queued image job. Automatic illustrator runs asynchronously after complete turn, independent of next chat turn. GET updates show results. Revision/branch guards reject late writes/images after edits or rewind. version changes only for story-semantic mutations, not image job/status updates.

## UI

Later additions: optional settings.helperModel (blank means chatModel) routes interpreter, independent introduction curator and memory requests. Introduction curation sees the narrator's available history and world, but retrospective memories require an earlier narrator identity citation and exact eligible source excerpts. Store provenance with character knowledge in snapshots. Observations record localBroadcast so restricted/remote delivery cannot become a retrospective event source. Messages may include storyTime and sourceEventId for chronology and provenance. GET /api/stories/:id/debug returns no-store text/plain with local request/response/error records; logs are not part of story exports or fictional rewind state.

Vanilla buildless JS, no CDNs. Mobile-first polished dark warm library aesthetic with ivory text, amber/sage accents, serif narrative and readable UI font using system stacks. App feels like a focused continuous conversation, with discreet speaker identities rather than forced scenes. Responsive left library drawer, top story header, main scroll chat, anchored composer. Empty onboarding/start screen includes freeform premise, player persona, optional main cast. Message action menus copy/edit/delete/rewind (all roles), regeneration/continue controls, busy stage and stop. Edit/delete dialog explains new branch preserving old future. Branch selector, image gallery/lightbox, reference/prompt details. Settings dialog with distinct general roleplay and illustrator prompt textareas, proxy/model settings, autogeneration settings; model connection check. Inspector drawer for whereabouts/time, knowledge incl sources, public info. Save status, meaningful errors, import/export download. Accessible keyboard focus, Escape closes modal, mobile touch targets. Do not render user/model content using raw innerHTML: construct nodes/textContent or sanitize if needed. Use simple text formatting via CSS white-space:pre-wrap; no third-party Markdown package needed. No fake AI fallback. Offer empty state and connect instructions when proxy absent. Label live connection state. Header/footer unobtrusive technology details in settings/setup only.
